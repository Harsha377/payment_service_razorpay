# Payout Database Fields

The `payouts` table stores both our business information and the latest state received from Razorpay.

---

## status

### Description

Represents the current payout status in our application.

### Possible Values

- CREATED
- PENDING
- PROCESSING
- PROCESSED
- FAILED
- REVERSED
- CANCELLED

### Updated By

- Create Payout API
- Razorpay Webhooks

### Example

CREATED

↓

PROCESSING

↓

PROCESSED

---

## gateway_response

### Description

Stores the complete webhook payload received from Razorpay as JSON.

### Why do we store it?

Instead of storing only individual fields, we store the entire gateway response.

Benefits

- Debugging
- Audit history
- Future compatibility
- Customer support
- Financial investigation

Example

```json
{
  "event":"payout.processed",
  "payload":{
      ...
  }
}
```

---

## failure_reason

### Description

Stores the reason why the payout failed.

### Example

- Invalid Account Number
- Beneficiary Bank Offline
- Account Frozen
- IFSC Invalid

Example

```
Invalid beneficiary account number.
```

### Updated During

- payout.failed webhook

---

## utr

### Full Form

Unique Transaction Reference

### Description

A unique transaction reference generated by the banking network after the money has been transferred successfully.

Example

```
HDFC250721123456
```

### Why do we store it?

Customer says

> I didn't receive the payout.

Support can provide

```
UTR

HDFC250721123456
```

The beneficiary can contact their bank using this UTR to trace the transaction.

### Updated During

- payout.processed webhook

---

## fees

### Description

Processing fee charged by Razorpay.

Stored in the smallest currency unit.

Example

Payout

₹1000

↓

Razorpay Fee

₹5

↓

Stored

500

(500 paise)

### Why store it?

Useful for

- Accounting
- Expense reports
- Settlement reports

Updated During

- payout.processed webhook

---

## tax

### Description

GST or tax charged on the Razorpay processing fee.

Example

Fee

₹5

GST

₹0.90

Stored

90

(90 paise)

### Why store it?

Used for

- Tax reporting
- Accounting
- GST reconciliation

Updated During

- payout.processed webhook

---

## processed_at

### Description

Stores when the payout was successfully completed.

Example

```
2026-07-25 11:45:30
```

### Why store it?

Useful for

- SLA monitoring
- Reporting
- Customer support

Updated During

- payout.processed webhook

---

## failed_at

### Description

Stores when the payout failed.

### Why store it?

Allows operations teams to know exactly when the failure occurred.

Updated During

- payout.failed webhook

---

## reversed_at

### Description

Stores when the payout was reversed after processing.

### Why store it?

Useful for

- Financial reconciliation
- Refund investigations
- Bank dispute resolution

Updated During

- payout.reversed webhook

| Feature                                    | Purpose                                     | Used When                                                  |
| ------------------------------------------ | ------------------------------------------- | ---------------------------------------------------------- |
| **Webhook**                                | Automatically synchronize payout status     | Normal production flow                                     |
| **GET /v1/payouts/{id}**                   | Fetch the latest payout state from Razorpay | Reconciliation, admin refresh, customer support, debugging |
| **gateway_response**                       | Store the complete webhook payload          | Auditing and troubleshooting                               |
| **utr**                                    | Bank transaction reference                  | Track successful transfers with the bank                   |
| **fees**                                   | Razorpay processing fee                     | Accounting and settlement                                  |
| **tax**                                    | Tax on processing fee                       | GST/tax reporting                                          |
| **processed_at / failed_at / reversed_at** | Lifecycle timestamps                        | Reporting, SLA monitoring, and reconciliation              |
