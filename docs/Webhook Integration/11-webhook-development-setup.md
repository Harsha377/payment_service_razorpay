# Credential Overview

The Razorpay integration uses three different credentials.

Each credential has a different purpose and security requirement.

| Credential | Created By | Purpose | Exposed to Frontend |
|------------|------------|---------|---------------------|
| Key ID | Razorpay | Identify the merchant account and open Razorpay Checkout | ✅ Yes |
| Key Secret | Razorpay | Create Orders, Fetch Payment Details, Verify Checkout Signature | ❌ No |
| Webhook Secret | Developer (You) | Verify Razorpay Webhook Requests | ❌ No |

These credentials should never be confused because each one serves a completely different purpose.

---

# Razorpay Key ID

The **Key ID** is generated by Razorpay when API Keys are created.

Example

```text
rzp_test_TCtwQyWAY16XYZ
```

Purpose

- Identifies your Razorpay merchant account.
- Used by Razorpay Checkout.
- Required by the frontend to open the payment popup.

Example

```javascript
const options = {
    key: "rzp_test_TCtwQyWAY16XYZ",
    order_id: "order_Q2ABC123"
};
```

Security

The Key ID is **public** and is designed to be visible in the browser.

It does **not** provide permission to perform payment operations.

---

# Razorpay Key Secret

The **Key Secret** is generated by Razorpay together with the Key ID.

Example

```text
8mL5pG2xYwT7Qv9AbCdEfGhIjKlMnOp
```

Purpose

The backend uses the Key Secret for:

- Creating Razorpay Orders
- Fetching Payment Details
- Verifying Checkout Signatures
- Authenticating Razorpay API Requests

Current Usage in StreamHub

```text
Spring Boot

↓

Create Order

↓

Fetch Payment

↓

Verify Signature
```

Security

The Key Secret is **strictly confidential**.

It must:

- Never be returned in an API response.
- Never be stored in frontend code.
- Never be committed to Git.
- Never appear in browser developer tools.

Only the backend should have access to it.

---

# Webhook Secret

Unlike the Key ID and Key Secret, the **Webhook Secret is not generated by Razorpay**.

The developer creates this value while configuring a webhook.

Example

```text
streamhub-payment-webhook-test
```

or

```text
MySecureWebhookSecret2026!
```

The exact same value must be configured in two places.

### Razorpay Dashboard

```text
Webhook Secret

↓

streamhub-payment-webhook-test
```

### Spring Boot Configuration

```yaml
razorpay:
  webhook-secret: streamhub-payment-webhook-test
```

Purpose

The Webhook Secret is used only to verify that webhook requests genuinely originated from Razorpay.

It is **never** used for:

- Creating Orders
- Fetching Payments
- Opening Checkout

Security

Like the Key Secret, the Webhook Secret must remain private and should never be exposed to the frontend.

---

# Summary

The three credentials have different responsibilities.

```text
Key ID
│
├── Created by Razorpay
├── Public
└── Used by Frontend (Checkout)

Key Secret
│
├── Created by Razorpay
├── Private
└── Used by Backend (Orders, Payments, Signature Verification)

Webhook Secret
│
├── Created by Developer
├── Private
└── Used by Backend (Webhook Verification)
```

Keeping these credentials separate improves security, simplifies credential rotation, and follows the principle of least privilege.
